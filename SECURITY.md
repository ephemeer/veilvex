# Безопасность формы заявки (`POST /api/contact`)

Документ описывает серверную часть формы «Обсудить проект»: что она делает, какие меры защиты
реализованы в коде, какие переменные окружения нужны и что остаётся на стороне людей и панелей
хостинга. Чек-лист, по которому проектировалась функция, — `.claude/skills/vibe-security-audit/SKILL.md`.

## Что делает функция

| Файл | Назначение |
|------|------------|
| `functions/api/contact.ts` → `netlify/functions/lib/cloudflare.ts` | Точка входа **Cloudflare Pages Functions** (основной хостинг): `onRequest` на `/api/contact`. Собирает зависимости: строковые переменные окружения (`CONTEXT` всегда `production`, `URL` — origin запроса, так что same-origin проверка работает на `*.pages.dev`, превью и своём домене без настройки), `fetch`, часы, KV `RATE_LIMIT` (с откатом в память и записью в лог), IP из `CF-Connecting-IP`. Покрыто `tests/cloudflare.test.ts`. |
| `netlify/functions/contact.mts` | Точка входа Netlify (запасной хостинг) Functions v2 (`export default (req, context)`), `config.path = '/api/contact'`, платформенный `rateLimit`. Собирает реальные зависимости: env, `fetch`, часы, хранилище Netlify Blobs (с откатом в память), JSON-логгер. |
| `netlify/functions/lib/contact-core.ts` | Вся логика в виде чистой фабрики `createContactHandler(deps)`. Зависимости (`fetch`, `now`, `env`, `store`, `log`) подставляются снаружи, поэтому код полностью покрыт юнит-тестами (`tests/contact.test.ts`). |
| `scripts/dev-api.mjs` | Локальный запуск функции на `http://127.0.0.1:8788` (`npm run api:dev`); `astro dev` проксирует туда `/api/*`. |
| `scripts/serve-secure.mjs` | Раздача `dist/` с заголовками из `netlify.toml` + та же функция на `/api/contact` (`npm run serve:secure`). |

Контракт запроса (фронтенд шлёт ровно это, `Content-Type: application/json`):

```json
{
  "name": "string, 2–80 символов",
  "contact": "string, 5–120 символов (телефон / Telegram / e-mail)",
  "services": ["geo", "seo", "ads", "site", "app", "ai", "improve", "design", "smm"],
  "message": "string, 0–2000 символов",
  "consent": true,
  "lang": "ru | en | az | de",
  "website": "",
  "t": 1700000000000
}
```

`website` — honeypot (должен быть пустым), `t` — время (epoch ms), когда форма была отрисована.

Ответы (всегда JSON, всегда `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, без CORS):

| Код | Тело | Когда |
|-----|------|-------|
| 200 | `{ "ok": true }` | Доставлено хотя бы по одному каналу — **или** запрос распознан как бот (тихий сброс, ничего не отправляется). |
| 400 | `{ "ok": false, "error": "invalid_json" }` | Тело — не JSON / не UTF-8 / пустое. |
| 400 | `{ "ok": false, "error": "validation", "fields": ["name", …] }` | Не прошла схема. Наружу — только имена полей, без текстов ошибок и без эха введённых данных. |
| 403 | `{ "ok": false, "error": "forbidden" }` | Чужой `Origin` или `Sec-Fetch-Site` не `same-origin`/`none`. |
| 405 | `{ "ok": false, "error": "method_not_allowed" }` + `Allow: POST` | Любой метод, кроме POST. |
| 413 | `{ "ok": false, "error": "payload_too_large" }` | Тело больше 16 КБ (по `Content-Length` **и** по фактически прочитанным байтам). |
| 415 | `{ "ok": false, "error": "unsupported_media_type" }` | `Content-Type` не `application/json`. |
| 429 | `{ "ok": false, "error": "rate_limited", "retryAfter": 540 }` + `Retry-After` | Превышен лимит заявок с одного IP. |
| 502 | `{ "ok": false, "error": "delivery_failed" }` | Все настроенные каналы доставки упали. |
| 503 | `{ "ok": false, "error": "not_configured" }` | Ни один канал не настроен (нет переменных окружения). |
| 500 | `{ "ok": false, "error": "server" }` | Любая непредвиденная ошибка; подробности — только в серверном логе. |

## Реализованные меры защиты

Порядок проверок в `contact-core.ts` (каждая покрыта тестом в `tests/contact.test.ts`):

1. **Метод и тип содержимого.** Только `POST` (иначе 405 + `Allow: POST`), только `application/json`
   (иначе 415). Это отсекает классические HTML-формы и `text/plain`-запросы с чужих сайтов.
2. **Лимит размера тела — 16 КБ.** Проверяется заголовок `Content-Length`, а затем поток тела читается
   с подсчётом байт и обрывается, как только лимит превышен (413). Невалидный UTF-8 и битый JSON → 400.
3. **Same-origin (защита от CSRF).** Если есть `Sec-Fetch-Site`, он должен быть `same-origin` или `none`.
   Если есть `Origin`, он должен входить в allow-list, собранный из `SITE_URL`, `URL`, `DEPLOY_PRIME_URL`,
   `DEPLOY_URL` (три последних Netlify задаёт сам, поэтому deploy-preview и branch-deploy работают
   без настройки). Локальные origin'ы (`http://localhost:4321`, `http://127.0.0.1:4321`,
   `http://localhost:4322`, `http://127.0.0.1:4322`) добавляются только при `NETLIFY_DEV`, `CONTEXT=dev`
   или когда `CONTEXT` не задан вовсе и `NODE_ENV !== 'production'` — в задеплоенной функции `CONTEXT`
   задан всегда, поэтому localhost в прод не попадает. Запрос без обоих заголовков (curl, скрипты)
   пропускается — для него всё равно действуют валидация и rate limit. CORS-заголовков нет вообще:
   API только same-origin.
4. **Строгая серверная валидация (zod).** `z.strictObject` — любое неизвестное поле отклоняется
   (защита от mass assignment: сервер принимает ровно задокументированный контракт). Поля: `name`
   2–80, `contact` 5–120, `message` 0–2000 (длины считаются после очистки), `services` — только id из
   белого списка, без дубликатов, до 9 штук, `consent` — литерал `true`, `lang` — enum, `t` — целое
   неотрицательное число. Из всех строк удаляются управляющие символы (C0/C1, DEL), zero-width и
   bidi-символы (U+200B–U+200F, U+202A–U+202E, U+2060–U+2069, BOM), пробелы схлопываются, в `message`
   нормализуются переводы строк и допускается максимум одна пустая строка подряд.
5. **Антибот без капчи.** Заполненный honeypot `website`, слишком «быстрая» отправка (`t` моложе 3 с),
   устаревшая форма (`t` старше 24 ч) или `t` из будущего (больше `now + 60 с`) → ответ `200 { ok: true }`
   **без доставки** и запись `bot_dropped` в лог. Бот не получает сигнала, что его распознали, и не
   расходует лимит заявок.
6. **Ограничение частоты** — два уровня, см. раздел ниже.
7. **Доставка только как простой текст.** Telegram: `sendMessage` с полем `text`, **без `parse_mode`**
   и с `disable_web_page_preview: true` — пользовательский ввод не может стать разметкой, ссылки не
   разворачиваются. Resend: только поле `text`, без `html`. Шаблон фиксированный, подписи
   (Имя/Контакт/Услуги/Задача) берутся по `lang` запроса. На каждый внешний вызов — таймаут 8 с через
   `AbortController`. Каналы вызываются параллельно (`Promise.allSettled`): один успех → 200, все
   упали → 502, ничего не настроено → 503 и понятное сообщение в логе.
8. **Общие тексты ошибок наружу.** Клиент видит только короткие коды (`validation`, `rate_limited`,
   `server` …) и имена полей. Весь обработчик обёрнут в `try/catch`: любая непредвиденная ошибка → 500
   `server`, настоящая ошибка — в лог. Стектрейсы и внутренние сообщения наружу не уходят.
9. **Гигиена логов.** Логируются только имена событий, статус, причина и первые 8 символов
   SHA-256 от IP. Имя, контакт и текст заявки в лог не попадают никогда. Значения
   `TELEGRAM_BOT_TOKEN` и `RESEND_API_KEY` вырезаются из любых сообщений об ошибках (`redact`), а URL
   вида `/bot<token>/` маскируется дополнительно — токен не может оказаться ни в логе, ни в ответе.
10. **Секреты только в переменных окружения.** В коде и в бандле фронтенда токенов нет; `.env*` в
    `.gitignore`, в репозитории лежит только `.env.example` с пустыми значениями.

## Переменные окружения

Задаются в Cloudflare: проект Pages → *Settings → Variables and Secrets*, окружение Production (токены — тип Secret); на Netlify — *Site configuration → Environment variables* (для локальной разработки — файл `.env`,
который читают `scripts/dev-api.mjs` и `scripts/serve-secure.mjs`).

| Переменная | Обязательна | Назначение |
|------------|-------------|------------|
| `SITE_URL` | на Cloudflare — да | Публичный URL сайта: из него собираются canonical, sitemap, robots.txt, llms.txt и JSON-LD; добавляется в allow-list `Origin` (на Netlify задавать не нужно — там есть `URL`, `DEPLOY_PRIME_URL`, `DEPLOY_URL`). |
| `TELEGRAM_BOT_TOKEN` | канал 1 | Токен бота от `@BotFather`. |
| `TELEGRAM_CHAT_ID` | канал 1 | ID чата/группы, куда слать заявки. |
| `RESEND_API_KEY` | канал 2 | Ключ API Resend. |
| `CONTACT_TO_EMAIL` | канал 2 | Куда отправлять письмо. |
| `CONTACT_FROM_EMAIL` | канал 2 | От кого (домен должен быть верифицирован в Resend). |
| `CONTACT_RATE_LIMIT` | нет | Заявок с одного IP за окно (по умолчанию 5). |
| `CONTACT_GLOBAL_RATE_LIMIT` | нет | Общий потолок заявок со всех IP за то же окно (по умолчанию 60). |
| `CONTACT_RATE_WINDOW` | нет | Окно в секундах (по умолчанию 600). |

Канал включается, только если заданы **все** его переменные (полузаполненный канал игнорируется).
Нужен хотя бы один канал, иначе функция честно отвечает 503 `not_configured`.

## Как работает ограничение частоты

**Уровень 1 — край сети.** На Cloudflare Pages — правило Rate limiting в WAF (на бесплатном плане одно правило; доступно, когда домен подключён к Cloudflare как зона): *Security → WAF → Rate limiting rules* → URI Path equals `/api/contact`, 10 запросов за 10 секунд с IP → Block на 10 секунд. Без своего домена на `*.pages.dev` этого слоя нет, работают уровень 2 и встроенная защита Cloudflare. На Netlify — в `contact.mts`:

```ts
export const config = { path: '/api/contact', rateLimit: { windowLimit: 10, windowSize: 60, aggregateBy: ['ip', 'domain'] } };
```

10 запросов за 60 секунд на пару IP + домен. Срабатывает на краю сети **до** запуска функции — флуд не
тратит ни инвокации, ни время; клиент получает 429 от платформы.

**Уровень 2 — скользящее окно в самой функции.** По умолчанию 5 заявок за 600 секунд с одного IP
(`CONTACT_RATE_LIMIT` / `CONTACT_RATE_WINDOW`).

- IP на Cloudflare — из `CF-Connecting-IP` (заголовок ставит сам Cloudflare, клиент его не подделает). На Netlify — из `context.ip`, затем из `x-nf-client-connection-ip`, затем из первого значения
  `x-forwarded-for`, иначе `unknown`. В хранилище и в логи попадает только `SHA-256(ip)` — сырые адреса
  не сохраняются нигде.
- Для ключа хранится массив меток времени (epoch ms) принятых заявок. При запросе метки старше окна
  отбрасываются; если осталось ≥ лимита — 429 с заголовком `Retry-After` и полем `retryAfter`
  (секунды до выхода самой старой метки из окна). Отклонённый запрос **не** записывается и не
  продлевает блокировку.
- Учитываются только запросы, дошедшие до стадии доставки (прошли валидацию и антибот) — то есть это
  лимит именно на число отправленных заявок, а не на любой HTTP-трафик (его режет уровень 1).
- Хранилище на Cloudflare — KV-namespace, привязанный к проекту как `RATE_LIMIT`. Ключ живёт до конца окна (`expirationTtl`, минимум 60 с) и удаляется самим KV — чистить нечего. KV согласован в конечном счёте (между точками присутствия — до ~60 с), так что лимит между регионами мягкий, но в пределах одной точки — точный; при сбое KV — память инстанса и запись в лог. Проверено в локальном рантайме workerd (`wrangler pages dev`): 5 заявок проходят, с 6-й — 429.
- Хранилище на Netlify — Netlify Blobs, стор `contact-rate-limit` с `consistency: 'strong'`, поэтому лимит общий
  для всех инстансов функции и регионов. Blobs не умеет TTL: на каждый хеш IP остаётся маленький JSON
  (≤ 5 чисел) с меткой `expiresAt` в metadata; при желании его можно чистить периодически.
- Деградация: вне Netlify (`npm run api:dev`, тесты) `getStore()` бросает исключение → используется
  хранилище в памяти процесса (достаточно для локальной проверки). Если Blobs падает уже в рантайме,
  инстанс тоже переходит на память и пишет `rate_limit_store` в лог; если и это не удалось — проверка
  «пропускает» (fail-open), но событие `rate_limit_store_*_failed` попадает в лог, а уровень 1
  продолжает работать. Форма не ломается из-за сбоя вспомогательного хранилища.

## Что нельзя починить кодом

1. **Переменные окружения** задать в панели Cloudflare Pages (*Settings → Variables and Secrets*, токены — Secret) или Netlify,
   а не в репозитории. Проверить, что `.env` не закоммичен (он в `.gitignore`) и что в истории git нет
   токенов (`git log -p --all -S "TELEGRAM_BOT_TOKEN="`).
2. **Включить 2FA** на аккаунтах Cloudflare (и Netlify, пока он остаётся), регистратора домена/DNS, владельца Telegram-бота
   (аккаунт, с которого создан бот в `@BotFather`) и в Resend. Любой из них даёт полный контроль над
   сайтом или каналом заявок.
3. **Ротация секретов при утечке.** Токен бота отзывается командой `/revoke` в `@BotFather` (выдаётся
   новый, старый перестаёт работать мгновенно); ключ Resend — в панели Resend → API Keys. После
   ротации обновить переменные в Cloudflare и передеплоить (Retry deployment). Если токен когда-либо попадал в git, логи или
   чат — считать его утёкшим и менять, даже если признаков злоупотребления нет.
4. **Зависимости.** Держать `npm audit` (`npm run audit`) чистым, обновлять `astro`, `zod`,
   `@netlify/*`; `package-lock.json` остаётся в репозитории, версии закреплены точно.
5. **Доступ к репозиторию и деплоям.** Минимум людей с правами на проект Cloudflare и репозиторий; превью-сборки
   для публичных PR отключить (Settings → Builds → Preview deployments → None), если репозиторий станет публичным (превью выполняют функцию с
   боевыми переменными окружения).
6. **Мониторинг.** Периодически смотреть логи функции на события `rate_limited`, `bot_dropped`,
   `delivery_failed`, `contact_not_configured` — рост первых двух означает атаку, последние два —
   проблему с каналом или настройкой.

## DDoS и флуд

- **Статика** (все страницы, `/_astro/*`, картинки) раздаётся из кэша сети Cloudflare: запросы не доходят
  до кода, сетевые (L3/L4) и HTTP-флуд гасит встроенная бесплатная защита Cloudflare от DDoS (без лимита
  трафика). Хешированные ассеты кэшируются на год (`immutable`, `_headers`). Трафик статики на Pages
  бесплатный и безлимитный — «атака на кошелёк» через статику невозможна.
- **Единственная динамика — `POST /api/contact`.** Слои: (если домен в Cloudflare) правило Rate limiting в
  WAF на краю сети; затем в функции: тело ≤ 16 КБ (чтение обрывается сразу), проверка Origin, honeypot и
  время заполнения, лимит 5 заявок за 10 минут на адрес (для IPv6 — на /64) и 60 на весь сайт. Остальные
  методы → 405 без работы. Бесплатный тариф — 100 000 вызовов функции в сутки; при исчерпании функция
  отвечает ошибкой до конца суток, статика работает дальше, денег не списывается.
- **Что включить владельцу, когда домен будет в Cloudflare:** Security → Bots → Bot Fight Mode; одно
  правило Rate limiting для `/api/contact` (см. «Уровень 1»); при реальной атаке — Security → Settings →
  Under Attack Mode (проверка браузера для всех) и WAF Custom rules (блок стран/ASN/IP).
- **Netlify (запасной хостинг):** лимит платформы 10 запросов в минуту на IP + домен до запуска функции,
  плановая `purge-rate-limit` без публичного URL; на кредитном тарифе при исчерпании кредитов
  останавливаются деплои, перерасхода денег нет.

## Известные допущения

- SHA-256 от IP — псевдонимизация, а не анонимизация (пространство IPv4 перебирается). Для ключа
  rate limit этого достаточно, но хранилище всё равно считается содержащим персональные данные.
- Заголовки задаются в одном месте — `netlify.toml`; для Cloudflare `npm run gen:host` (в `prebuild`) переносит их в `public/_headers`. Платформа применяет их к статике; к ответам функций они могут не
  применяться, поэтому функция сама выставляет `Cache-Control: no-store` и
  `X-Content-Type-Options: nosniff`.
- Хранилище в памяти (локальный режим / откат) живёт в одном процессе; общий лимит между инстансами
  обеспечивает только Netlify Blobs; на Cloudflare KV — общий в конечном счёте (см. выше).


## Изменения после независимого аудита (2026-10-24)

Аудит по 20 пунктам не нашёл критичных и средних проблем. Применены усиления:

- **Fail-closed по Origin.** POST без заголовка `Origin` теперь отклоняется (403 `forbidden`, причина `missing_origin`): браузеры всегда отправляют `Origin` на POST, а единственный легитимный клиент — форма самого сайта. Для `curl` добавляйте `-H "Origin: https://<ваш-домен>"`.
- **Продакшн по умолчанию.** Если переменная `CONTEXT` не задана, функция считает окружение продакшном (localhost-origin'ы не принимаются), если только `NODE_ENV=development`. Локальные скрипты `dev-api` и `serve-secure` сами выставляют `CONTEXT=dev`; `CONTEXT=production` в их окружении включает прод-правила для проверки.
- **IPv6.** Ключ лимита частоты строится из префикса /64 (`rateLimitIdentity`), поэтому ротация адресов внутри одного префикса не сбрасывает лимит. IPv4 — без изменений.
- **Формат переменных Telegram.** Если `TELEGRAM_BOT_TOKEN` не похож на `123456:ABC…` (≥30 символов после двоеточия) или `TELEGRAM_CHAT_ID` — не целое число, канал считается ненастроенным, в лог пишется `telegram_env_malformed`, а при отсутствии других каналов форма отвечает 503 `not_configured` — громко, а не молчаливыми ошибками доставки.
- **CSP:** из `img-src` убран неиспользуемый источник `data:`.

Остались на стороне эксплуатации (см. раздел выше): переменные окружения в панели Netlify только для контекста production, 2FA, ротация токенов, проверка заголовков функции после первого деплоя (`curl -I https://<site>/api/contact`), периодическая очистка стора `contact-rate-limit`.

## Изменения после повторного аудита (2026-10-24, второй проход)

Критичных и средних проблем снова не найдено. Применены мелкие замечания и усиления:

- **Невидимые символы.** Санитайзер теперь вырезает все управляющие (`\p{Cc}`) и форматные (`\p{Cf}`) символы Unicode, включая TAG-символы U+E0000–E007F («ASCII smuggling»), U+061C, U+00AD, U+034F, U+180E, U+206A–206F — раньше часть из них проходила в текст заявки.
- **Шаблон сообщения.** Служебная строка `lang=… · дата` идёт перед текстом задачи, а каждая строка свободного текста начинается с `> `: подделать поля или футер внутри сообщения больше нельзя незаметно.
- **Общий потолок лимита.** Кроме окна на IP добавлен site-wide лимит `CONTACT_GLOBAL_RATE_LIMIT` (по умолчанию 60 заявок за `CONTACT_RATE_WINDOW`) — защита от ботнетов и ротации IPv6-префиксов.
- **Хранилище лимита.** После сбоя Netlify Blobs память используется временно (60 с), затем Blobs пробуется снова; раньше одна ошибка переводила инстанс на память навсегда.
- **`X-Robots-Tag: noindex`** ставится самой функцией: заголовки из `netlify.toml` к ответам функций не применяются.
- Локальный `serve-secure` принимает форму с любого порта (`SITE_URL` по умолчанию = адрес сервера в dev-контексте).
